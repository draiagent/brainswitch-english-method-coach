# 設計理念

本工具不是先做介面再想功能，而是先有一套學習方法（「多語學習三大核心策略」），再把每一條原則翻譯成一個可以按的按鈕。這份文件記錄每條原則怎麼落地，以及為什麼這樣實作。

---

## 策略一：環境營造與心態轉換

### 1. 建立外語腦：強迫切換理解模式
**實作：外語腦模式（中文遮罩）**

所有中文（釋義、搭配詞中譯、例句翻譯）預設以 CSS `filter: blur()` 模糊化，點擊個別區塊或按 `Z` 才揭曉。

*為什麼用模糊而不是隱藏？* 模糊保留了「那裡有東西」的視覺提示，學習者知道答案就在手邊，降低焦慮；完全隱藏會讓人不斷去找按鈕，反而打斷思考。

*限制*：資料集只有中文釋義、沒有英英釋義，所以無法做到純英文環境。目前的替代方案是「先讀英文例句與搭配詞來推測字義」。若未來換成含英英定義的資料集，這裡可以再強化。

### 2. 環境推動力：將外語塞進日常流程
**實作：連續學習天數 🔥**

跨日自動判定：昨天有學 → 天數 +1；中斷 → 歸零。存在 localStorage。

*為什麼不用總時數或總字數？* 連續性比總量更能驅動「每天打開它」的習慣，而習慣才是把外語塞進日常的機制。

### 3. 內容型學習：以完成任務取代時間量化
**實作：今日任務以「張數」計，主進度條顯示今日完成度**

介面上刻意**沒有任何計時器**。「今天讀了 30 分鐘」無法回答「所以我完成了什麼」，而「今天完成 20 張」可以。

### 4. 接受精神年齡：從簡單的自我溝通開始
**實作：程度設定（難度等級）**

五個等級（入門／基礎／中階／進階／精熟）對應資料集的 `難度等級` 欄位。設定面板的說明文字刻意寫「誠實從簡單的開始，比硬撐難字有效」——這條原則的關鍵是心態，不只是篩選器。

## 策略二：深度理解與高效輸入

### 5. 核心意象：抓住單字背後的具體畫面
**實作：意象筆記 ＋ 分類圖示色條**

- 意象筆記：學習者自己寫下畫面，存本機，下次自動帶回。
- 分類色條：15 種商用情境各配一個圖示與漸層色，讓單字掛在情境上。

*設計取捨*：原本考慮串接圖庫 API 顯示真實照片，但（a）Unsplash Source API 已停用，（b）其他圖庫需要 API 金鑰，而這是純前端工具、無後端可藏金鑰，(c) 關鍵字配圖經常牛頭不對馬嘴，反而干擾記憶。因此改用**情境圖示**，可靠且零依賴。真正的「意象」交給學習者自己寫——自己想出來的畫面本來就比別人給的圖好記。

### 6. 語言組塊：記憶道地的固定搭配詞
**實作：獨立的「語言積木 CHUNKS」區塊**

搭配詞從一般欄位獨立出來，加上左側色條、專屬朗讀鈕與複製鈕，視覺上強調它是「一整塊」而非零散資訊。朗讀時只取英文部分。

資料集中 9,782 字裡有 5,884 字含搭配詞；沒有的卡片會自動隱藏這一區。

### 7. 九秒記憶法：重視重複頻率而非單次強度
**實作：間隔重複排程（SM-2 精簡版）**

這是整個升級的核心。原本四個按鈕只是計數器，現在真正決定排程：

```
新卡：Again → 本回合稍後   Hard → 10 分鐘   Good → 1 天   Easy → 3 天
複習：Hard → 間隔 × 1.2    Good → 間隔 × 熟悉度   Easy → 間隔 × 熟悉度 × 1.3
熟悉度（ease）起始 2.5，Again −0.2、Hard −0.15、Easy +0.15，下限 1.3、上限 3.0
```

兩個刻意的設計：

1. **新卡間隔刻意很短**（10 分鐘 / 1 天），因為原則是「重複頻率優先」，不是一次背到熟。
2. **按 Again 的字會在本回合第 5 張後再出現一次**，把「重複」壓縮進當下這回合，而不是等到明天。

按鈕下方即時顯示下次間隔，讓學習者理解自己按的是「約下次見面時間」，而不是打分數。

### 8. i+1 選材：挑選比當前實力難一點的素材
**實作：i+1 選材開關 ＋ 高星級優先**

- 開啟時，題庫 = 你的難度等級 ＋ 高一階的等級。
- 新字排序依 `星級` 由高到低。資料驗證顯示星級與難度等級呈負相關（5 星集中在「入門」、1 星集中在「精熟」），代表**星級 = 常用度**：先學高頻字，投報率最高。

## 策略三：實戰輸出與技術應用

### 9. 寫作即高速口說：鍛鍊表達的精準度
**實作：造句練習 ＋ 朗讀自己的句子**

寫作是慢速的口說。輸入框旁的「朗讀我的句子」用語音合成把自己寫的句子念出來，銜接「寫得出來 → 說得出來」。

### 10. 區塊建築原則：直接搬用母語者的積木
**實作：一鍵複製語言積木／例句**

複製功能優先使用 `navigator.clipboard`，非安全內容（如 http 環境）自動退回 `execCommand` 方案，確保在教室的各種環境都能用。

### 11. AI 預編輯學習：優化結構後再進行翻譯
**實作：AI 提示詞產生器**

自動組出一段提示詞，明確要求 AI：

> 「請不要直接照我的中文思維直譯。先幫我『預編輯』：指出我的句子結構哪裡不像母語者，改寫成道地英文，並說明你改了什麼、為什麼。」

若學習者已存造句，會自動帶入。這條原則的重點是**改變提問方式**——不是叫 AI 翻譯，而是叫 AI 先重整結構並解釋。

*為什麼不直接串 AI API？* 那需要 API 金鑰，而純前端工具無法安全保管金鑰（寫在前端等於公開）。改用「產生提示詞 + 複製貼上」，功能等價、零風險、零成本，學習者也能順便學會怎麼問 AI。

### 12. 模仿與語音辨識：以機器理解作為合格標準
**實作：跟讀評分（Web Speech API）**

使用瀏覽器內建語音辨識，不需任何金鑰。

判定標準經過修正：**單字模式必須完整聽對才算合格**。初版用 Levenshtein 相似度，實測發現 `agility` 對 `ability` 相似度高達 86%，會誤判為「發音合格」——但那明明是聽成了另一個字。既然原則是「以機器理解作為合格標準」，機器聽成別的字就不能算過。目前：

- **單字**：辨識結果（含多組候選）需有一組與目標完全相同（忽略大小寫與標點）
- **例句**：詞彙覆蓋率 ≥ 70%，允許小幅漏字

## 整體技術取捨

| 決定 | 理由 |
|---|---|
| 單一 HTML 檔、無框架、無建置流程 | 老師要能直接下載一個檔案就用，不需要 npm |
| 資料獨立成 CSV 而非內嵌 | 3 MB 資料內嵌會讓檔案難以維護，也擋住「換自己的單字表」這個用法 |
| localStorage 而非雲端資料庫 | 零後端、零帳號、零隱私疑慮。代價是換裝置不同步，已在文件明確說明 |
| 不做成績報表 | 沒有後端就無法可信地驗證學習數據，與其做一個可以隨意造假的報表，不如明說沒有 |

---

## 已知限制

- **無跨裝置同步**：紀錄綁在單一瀏覽器。若要同步需要引入後端（如 Firebase），會改變本工具「零帳號」的定位。
- **語音辨識僅 Chromium 系瀏覽器**：Firefox 不支援，Safari 部分版本支援。
- **無英英釋義**：受限於資料集欄位，外語腦模式無法做到完全無中文。
- **共用電腦紀錄會混在一起**：工具無法分辨使用者。
